# 编剧部

编剧部位于 `story-original` 之后、`director-room` 之前。它负责把完整小说原著改编成一份结构化文学剧本主稿，让导演、配音、音乐、美术、提示词、视频和剪辑团队知道该拍什么、说什么、听见什么、保留什么。

***以作家之心写剧本，以敬畏之心对观众，以神圣感对待每一集的喜怒哀乐。***

`SKILL.md` 是部门入口和硬约束索引；完整工作流、主稿结构模板和长版创作信条写在 `references/workflow.md`。

## 零、编剧部创作信条

完整精神内核见 `references/workflow.md`，并由 `references/quality-gate.md` 纳入质检。

## 一、部门边界

编剧部负责：

- 每集一份结构化文学剧本主稿；
- 主稿内的分集、场次、分镜组和单分镜结构；
- 台词、旁白、字幕、角色声音、动作、表情、服装、环境、音乐和声音意图；
- 改编戏剧性、文学性、精神内核、质检和下游交接信息。
- 项目启用角色总卡时，负责每个角色文件中的 `Section 2. 编剧影视化角色卡`。

编剧部不负责：

- 角色总卡中的 `Section 1. 源头 Canon`、`Section 3. 美术视觉角色卡`、`Section 4. 配音声音角色卡`、`Section 5. 视频执行角色卡`；
- 最终导演调度和机位；
- `layout.yaml`；
- 图片生成；
- 视频生成；
- 配音音频生成；
- 配乐成品；
- ComfyUI / Wan / I2V 参数；
- 剪辑导出。

## 二、运行方式

编剧部采用“主协调代理 + 部门内子任务 / 子 agent + 质量门循环”。

可创建子任务：

```text
head-screenwriter-agent        总编剧
adaptation-writer-agent        改编编剧
scene-writer-agent             场次编剧
dialogue-writer-agent          对白编剧
character-behavior-agent       角色行为编辑
shot-script-agent              分镜剧本编辑
script-doctor-agent            剧本质检官
memory-evolution-agent         部门经验总结
```

若环境不支持子 agent，主协调代理按同样职责顺序执行。

## 三、硬约束

- 输入源、可读范围和正式输出路径由项目根目录 `project-management.md` 与项目办公室交接契约指定。
- 每集只允许有一份当前正式剧本主稿；具体文件名和路径由项目办公室指定。
- 整季汇总入口由项目办公室指定。
- 主稿必须按“一集 -> 分镜组 / 场景段落 -> 单分镜”结构写清全部生产信息。
- 不得把导演、配音、音乐、美术、提示词、视频和剪辑需要的信息拆散成多个强制输出文件。
- 项目启用角色总卡时，编剧部必须读取项目办公室指定角色总卡中的 `Section 1. 源头 Canon`，只写或更新 `Section 2. 编剧影视化角色卡`，不得修改源头 Canon、美术视觉、配音声音或视频执行区块。
- `Section 2. 编剧影视化角色卡` 必须服务影视剧本：戏剧功能、剧中人物目标、台词风格、口头禅、音色气口、情绪遮掩、常见动作、镜头里必须看见的状态、每集状态变化和禁止写偏项。
- 如果源头 Canon 不足以支撑影视化改编，状态必须写为 `needs_story_source_fix`，不得由编剧部自行改写源头事实。
- 如果项目办公室指定的原著正式材料缺失或资料不足，状态必须写为 `blocked_needs_story_original`，不得直接从背景和大纲硬写正式剧本。

编剧部可以自评、自返工、自总结经验，但不得自动修改 `.agents/skills/screenwriting/`。修改 skill 必须由用户明确要求。

## 四、质量门摘要

通过线：

```text
普通集：90
核心集：95
季终集：97
```

直接打回：

- 观众听不懂关键台词，或下游无法判断该拍什么；
- 主稿没有改编戏剧性、可见行动、转场因果、角色声音和行为提示；
- 项目启用角色总卡时，角色缺少 `Section 2. 编剧影视化角色卡`，或该区块背离源头 Canon；
- 只有结构，没有文学性、戏剧性和人的光。

完整评分表和失败条件见 `references/quality-gate.md`。
