# 故事原著质量门

质量门用于后台把关，不是公开稿的一部分。它必须同时检查故事工程、文学魅力和文字伦理：结构合格但不好看，或者好看但精神空洞、轻浮、污染心灵，都不能通过。

## 一、通过线

```text
普通章节：90
核心章节：95
终章 / 季终章节：97
全稿平均目标：94
```

## 二、评分表

| 维度 | 分值 | 检查问题 |
| --- | ---: | --- |
| 追读钩子 | 10 | 开头是否立刻产生危险、欲望、异样、问题或压力？ |
| 人物内驱 | 15 | 是否看见目标、恐惧、创伤和压力下行为？ |
| 冲突升级 | 15 | 压力是否层层加重，而不是重复说明？ |
| 场景沉浸 | 10 | 是否能感到光、声、温度、材质、气味和身体压力？ |
| 可见行动 | 10 | 事件是否能变成镜头和表演？ |
| 情绪推进 | 10 | 人物情绪是否发生变化，并留下余波？ |
| 悬念控制 | 10 | 信息释放是否清楚，悬念是否不是故意含糊？ |
| 高潮转折 | 10 | 转折是否来自选择、后果或发现？ |
| 文学质感与思想能量 | 10 | 语言、意象、节奏、人物声音是否有辨识度；作品是否有清楚的精神方向和思想能量？ |

所有维度都必须先通过 Bible 前提检查：章节使用的世界规则、人物关系、历史事件、关键道具功能和主线因果，必须来自项目现场契约指定的 `source_bible_file` 或由它明确推导。

## 三、模拟目标读者试读评分

质量门不得只做格式化 QC。每次隐藏 QC 必须在技术评分之外，单独给出 `reader_response_score`。它来自模拟目标读者试读，站在普通读者 / 目标读者视角，不站在作者、项目经理、设定整理者或流程验收者视角。

内置 QC 默认只做模拟目标读者试读，不自动声称或生成真实读者反馈：

```text
simulated_reader_agent_feedback: 子 agent 以目标读者身份试读，只能称为模拟读者试读。
internal_reader_simulation: 仅在当前环境无法创建子 agent 时作为降级方案，可信度低于子 agent 试读。
human_reader_feedback: 只在用户通过交互、真实试读者、评论区或平台材料明确提供后作为外部输入记录；不属于内置 QC 自动生成项。
```

优先创建 `target-reader-subagent` / `reader-test-subagent` 做模拟试读，但它不是人类读者。子 agent 试读时，只给公开正文、目标读者画像和阅读任务；不要给作者意图、预期答案、已有 QC 结论或希望它发现的问题。子 agent 输出必须标注为：

```text
reader_response_source: simulated_reader_agent_feedback
```

如果当前环境无法创建子 agent，只能由主协调代理降级模拟，必须标注为：

```text
reader_response_source: internal_reader_simulation
```

真实读者反馈需要独立的交互收集行为。只有用户主动提供、或明确要求收集真实试读 / 评论区 / 平台反馈，并给出原始反馈内容或可引用材料时，才可作为附加字段纳入：

```text
human_reader_feedback_source: user_feedback | test_reader_feedback | platform_feedback | mixed
human_reader_feedback_collection: 用户交互提供 / 外部试读整理 / 评论区摘录 / 平台反馈
```

不得伪造真实读者数据。没有真实反馈时，不写“真实读者认为”，只写模拟目标读者试读结论。

### 读者感受评分表

| 维度 | 分值 | 检查问题 |
| --- | ---: | --- |
| 入读顺滑度 | 15 | 普通读者是否能在前 1-3 段进入场景，而不是被设定、术语或作者腔挡住？ |
| 看懂成本 | 15 | 不查资料时，读者是否能明白谁在做什么、为什么急、失败会怎样？ |
| 情绪卷入 | 15 | 读者是否真的担心、愤怒、难过、紧张、心疼或好奇，而不是只知道作者想让他感动？ |
| 人物牵挂 | 15 | 读者是否开始在乎至少一个人物的命运、错误、关系或秘密？ |
| 追更欲 | 15 | 章末是否让读者愿意点下一章，而不是只觉得“结构完成了”？ |
| 厌烦 / 出戏控制 | 10 | 是否有明显的啰嗦、格言密集、专名堆叠、重复争论、作者自嗨或过度解释？ |
| 记忆点 | 10 | 读完后是否留下一个清楚的画面、动作、物件、台词、关系或问题？ |
| 传播欲 | 5 | 读者是否可能向别人描述这一章的亮点，而不是只说“设定挺复杂”？ |

通过建议：

```text
reader_response_score >= 80: 普通通过
reader_response_score >= 85: 重点章节通过
reader_response_score >= 90: 名著级 / 爆款级读者吸附力候选
reader_response_score < 75: 即使技术评分合格，也必须返工
reader_response_score < 65: 直接打回，优先重写读者入口、人物欲望和场景压力
```

### 必须写出的读者反馈字段

隐藏 QC 报告必须包含：

```text
reader_response_score:
reader_response_source: simulated_reader_agent_feedback | internal_reader_simulation
human_reader_feedback_source: 可选；仅在真实反馈已由用户提供或交互收集后填写
reader_entry_point: 读者从哪一刻进入故事
reader_dropoff_risk: 读者最可能在哪一段想跳过或弃读
reader_confusion_points: 不查设定会看不懂的点
reader_emotional_hits: 真正打到人的情绪点
reader_memory_points: 读后记得住的画面 / 动作 / 物件 / 关系
reader_next_chapter_desire: strong | medium | weak | none
reader_plain_language_verdict: 用普通读者口吻写一句直白评价
```

### 读者感受打回项

以下情况必须打回或返修，不能被结构分、格式分、设定完整度掩盖：

- 技术结构完整，但读起来无聊、费劲、像资料或像作者自嗨；
- 读者看不清本章谁想要什么、怕什么、出了什么事；
- 世界观和专名压过人物，普通读者需要反复查设定才能继续；
- 情绪被作者告诉读者，而读者自己没有感到；
- 读者没有追更欲，也没有任何可记住的人、画面、动作、关系或问题；
- 读者烦躁点、困惑点或弃读点明显，却被流程分数掩盖。

## 四、世界名著级加严项

当目标是“世界名著级”“大文豪级”“文学史级”或用户要求严肃文学评价时，必须在普通 100 分章节表之外加严判断。内部通过分不等于世界名著标准。

重点检查：

- 长篇厚度：是否有足够生活肌理、闲笔、社会细部和人物私生活；章节不能只像剧情节拍或分镜梗概。
- 人性复杂度：角色是否会误判、自私、犹豫、逃避、说错话和付出后果；不能人人都天然说出正确主题。
- 主题显影方式：主题是否由行动、代价、冲突和余波显影；不得频繁用格言、口号或作者判词替代人物选择。
- 声部差异：叙述、制度文书、群体口语、行业话语、儿童、老人、执行者、管理者、底层、外来者不能全是同一种冷硬史诗腔。
- 生活杂质：庄严场面必须有庸常细节托底，例如饭食、钱粮、病痛、衣物、气味、脏污、玩笑、偏见和讨价还价。
- 意象宽度：不能长期依赖同一组颜色、物件、抽象词和句式；每个新区域要有不同地方质地。

世界名著级返工优先处理：

```text
降低口号密度
扩写生活肌理
增加人物私心和错误
让主题通过行动和后果显影
把宏大命题落到饭、账、门、路、伤、钱、亲人和身体代价
```

## 五、文学魅力加严项

以下问题不一定单项归零，但会显著扣分：

- 语言像说明书，缺少人物感和节奏；
- 章节像多个作者拼接，段落声音、审美和叙述距离不统一；
- 场景只有“大”“黑”“美”“压抑”等抽象形容；
- 人物情绪被作者解释，而不是通过动作、选择、沉默、身体反应表现；
- 章节没有令人记住的意象、道具、动作或句子；
- 爽点、虐点、悬疑点或情感点没有被充分铺垫和释放；
- 所有角色说话像同一个人。

## 六、对白可听性加严项

以下问题必须扣分，严重时直接打回：

- 对白像主题宣言，不像人在具体处境下说话；
- 高频使用“不是 A，而是 B”“没有 A，只有 B”，造成类型化辩论腔、空洞哲理腔或碑刻腔；
- 一句台词塞入多个设定名词或专有概念，读者或观众需要查设定才懂；
- 用谜语、半句、暗语、反问或诗性意象交代关键剧情信息，但没有立即说明行动后果；
- 人物不先说现实欲望和恐惧，直接谈身份归属、命运宿命、权力名分、历史债务、组织使命、宏大理念等抽象概念；
- 制度角色、管理者、底层、儿童、老人、执行者、流动者、外来者、专业人士说话没有声部差异；
- 台词朗读时拗口、过长、信息堆叠，演员难以自然说出口。

对白通过标准：

```text
普通人物先说眼前事：身体、安全、时间、钱、工作、亲人、关系、路、门、工具、证据、权限、账、风险；具体例子随题材替换。
权力机构、组织、制度和专业系统台词短、硬、带后果。
每段对白原则上只承载一个设定名词或专有概念。
角色提出要求时先直说目的，再允许补一句隐喻。
高亮格言只用于高潮选择、人物弧线转折和终局余波。
```

## 七、文字伦理与精神方向

以下问题必须严肃扣分，严重时直接打回：

- 只有刺激、猎奇、爽点或反转，没有任何值得读者带走的精神能量；
- 消费苦难、羞辱人物、玩弄创伤，却没有悲悯、反思或后果；
- 把恶、虚无、犬儒、残酷写成廉价快感，而不是作为人物和世界的真实压力；
- 主题口号化，用说教替代人物选择和命运后果；
- 文字粗糙轻浮，缺少对语言、人物和读者心灵的敬畏。

## 八、直接失败项

出现以下任一项，直接失败：

- 章节主要是世界观说明；
- 主要人物没有目标；
- 场景没有可见行动；
- 对白负责解释世界，而不是表现压力；
- 结尾没有钩子或余波；
- 违背已锁定 canon；
- 使用 `source_bible_file` 之外的重大故事前提；
- 无法说明下游用途；
- 正文公开稿混入大量管理表、评分表或流程说明；
- 文学表达平庸到无法形成阅读吸引力。
- 故事精神方向严重空洞、恶俗，或以污染心灵的方式消费人物和读者。
- 公开正文未经过总小说家统一主笔、改写或最终裁决，呈现明显多人拼贴感。
- 关键对白需要额外解释世界观才能听懂，且没有动作、后果或上下文补足。
- 严肃文学目标下，全文只有剧情推进和主题宣言，没有生活肌理、人物私心和人性暧昧。
- `reader_response_score < 65`，或模拟目标读者试读 / 已收集的真实反馈显示明显无聊、困惑、出戏、无追更欲。

## 九、隐藏质检报告

隐藏报告写入项目现场契约指定的原著部隐藏质检位置，例如契约中的 `story_doctor_report_file`。不得在质量门中硬编码项目路径。

```text
story_doctor_report_file
```

必须包含：

```text
overall_status
bible_status
source_bible_file
source_ledger_file
full_text_score
reader_response_score
reader_response_source
reader_entry_point
reader_dropoff_risk
reader_confusion_points
reader_emotional_hits
reader_memory_points
reader_next_chapter_desire
reader_plain_language_verdict
chapter_scores
failed_chapters
rewrite_requirements
character_risks
plot_risks
immersion_risks
literary_risks
chief_novelist_unity_risks
spiritual_energy_risks
screenwriting_handoff_risks
approved_for_screenwriting: true|false
```

只有所有必需故事材料存在、公开正文干净、章节通过质量门，且读者感受分未低于打回线时，才能写：

```text
approved_for_screenwriting: true
```
