# 导演部门调度工作流

总导演代理是导演部内部唯一主创者、命令发布者和最终裁决者。员工子任务是总导演的手和脚，不是平行主创；不得继续派生员工，不得向用户发问，不得写共享文件，只返回 artifact envelope。

导演部已经收缩为导演判断、镜头语言、空间调度、连续性和质量闸门部门。它不执行图像生成、视频生成、ComfyUI 提示词工程、配音、音乐、剪辑、后期或交付生产。

导演部只有一个明面正式包根目录。该根目录必须按“季 -> 集 -> 分镜组 -> 分镜文件”逐层组织；每个分镜一个完整文件，集中承载运镜、动作、人物、场景、光影、声音、转场、连续性、后续部门要求和 QC。

## 总导演主创原则

- 总导演代理必须先建立本集作者意图、观看秩序、情绪节奏、审美纪律和质量铁律，再让员工执行。
- 员工只负责完成总导演命令下的具体工作，不能自立风格、重设导演意图或用专业建议推翻总导演裁决。
- 员工产物是候选执行稿，达到格式和分数要求只代表可以进入总导演审判。
- 总导演可以采用、打回、重组、删除或强化任何员工产物；只有总导演签署后，内容才算完成。

## 项目办公室交付优先

导演部启动前必须先接收项目办公室准备的导演启动包。项目办公室负责读取 `project-management.md`、解释 `.project/` 契约、整理允许输入、指定正式包根目录、维护台账、历史归档和交接索引。

未交付导演启动包时，状态为：

```text
blocked_needs_project_office_handoff
```

启动包不完整时，状态为：

```text
blocked_incomplete_project_office_handoff
```

导演部不得从 skill 中临时读取项目管理文件、拼输入路径、输出路径、隐藏工作区或交接索引。

## 子任务与顶层任务

- 每个员工是当前导演部门流程中的子任务。
- 不创建新的顶层项目、顶层线程或脱离当前项目根的新任务空间。
- 若运行环境没有子任务能力，总导演代理按同一创作顺序执行各员工职责。
- 若运行环境必须把员工隔离为独立任务，总导演代理必须使用同一导演启动包、同一分镜层级、同一总导演命令和同一评审规则。

```text

总导演命令：

导演启动包：
<项目办公室提供的导演启动包摘要>

Artifact 契约：
员工只返回导演部当前正式包的包索引或分镜文件内容草案，不直接写正式文件。

输入：
<本角色需要的、导演启动包允许使用的材料>

只返回结构化 envelope 和完整候选执行稿。
不要直接编辑文件。
不要调用其他员工。
不要执行图片、视频、音频、剪辑、后期或提示词生产。
不要把运镜、动作、人物、场景、光影、声音、转场、连续性或 QC 拆成不同明面文件。
```

## 依赖顺序

- 接收项目办公室导演启动包。
- 启动包完整性校验通过后，运行 `director-agent`。
- 总导演签署 `director-agent` 的导演阐述后，运行 `director-academy-agent`，把导演技法、外部学习源和本集风险转成非任意镜头规则。
- 总导演签署 `director-academy-agent` 的导演学院规则后，运行 `scene-breakdown-agent` 与 `visual-continuity-agent`。
- 总导演签署两者执行稿后，运行 `shot-planner-agent`。
- 总导演签署 `shot-planner-agent` 后，运行 `scene-coordinate-agent`，形成每个分镜文件的空间调度内容。
- 总导演签署 `scene-coordinate-agent` 后，运行 `cinematographer-agent`。
- 总导演签署 `cinematographer-agent` 后，运行 `storyboard-agent`。
- `storyboard-agent` 完成分镜文件草案后，运行 `storyboard-doctor-agent`、`transition-doctor-agent` 和 `audience-blind-qc-agent`。
- 总导演逐个签署通过分镜医生、转场医生和观众盲测 QC 的分镜文件后，运行 `handoff-package-agent`。
- 总导演签署 `handoff-package-agent` 后，运行 `director-qc-agent`。
- 若存在人工审核反馈，运行 `user-feedback-triage-agent`，再把返工项退回受影响员工。
- 所有内容被总导演签署后，总导演代理装配一个按季、集、分镜组、分镜文件存放的导演部当前正式包。

## 单包原则

导演部只有一个明面正式入口：项目办公室启动包指定的导演部当前正式包根目录。

正式包必须包含项目办公室启动包映射的层级：

- 季；
- 集；
- 分镜组；
- 分镜文件。

每个分镜文件必须完整包含项目规范摘要、本集导演意图、场景拆解、视觉连续性、镜头目的、摄影与分镜、空间调度、后续部门导演要求、导演 QC 和交接摘要中与该分镜相关的内容。包索引只负责定位、排序和状态说明，不能替代分镜文件。

正式包不得包含 `camera.md`、`action.md`、`characters.md`、`scene.md`、`lighting.md`、`sound.md` 等按维度拆开的明面文件。

评分记录、返工记录、员工草稿、JSON/YAML 结构化中间物和旧版本必须进入项目办公室指定隐藏工作区、历史归档或项目办公室台账，不得进入明面目录。

## 镜头与分镜连续规划

镜头和分镜必须先整体连续规划，再进入后续部门生产。

- `shot-planner-agent` 必须一次性整体处理本集所有场景与镜头，产出分镜组、分镜 ID、顺序和基础镜头信息；不得按单镜头孤立派工生成镜头顺序。
- `storyboard-agent` 必须一次性整体处理本集分镜计划，并把每个分镜装配成一个完整文件，确保相邻分镜的轴线、机位、动作方向、视线方向、光线、道具状态、角色站位、入镜状态、出镜状态和转场动机连续。
- 总导演代理只有在完整分镜组索引、全部分镜文件、分镜医生诊断、转场医生合同和观众盲测 QC 被总导演签署后，才能把导演部当前正式包交给后续生产环节。
- 后续部门可以拆分逐镜头执行，但不得重排镜头、重设场景、重放角色或改变道具位置。

## 空间调度

空间调度是每个分镜文件中的必备内容，不默认输出独立明面文件。项目办公室启动包明确要求机器可读附录时，才可写入隐藏工作区或指定附录路径。

空间调度必须说明：

1. 场景坐标原点、单位、轴向、尺寸和比例。
2. 固定结构、门窗、家具、道具、光源和出入口。
3. 角色在每个镜头中的起点、终点、朝向、视线方向和运动路径。
4. 摄影机位置、高度、朝向、焦段、视角和运动路径。
5. 禁止改变的空间关系、道具状态和连续性锁点。
6. 后续部门需要补充或验证的控制图、首帧、尾帧、低模或其他空间证据。

若用户或评审认为空间关系不成立，优先返工空间调度和场景坐标判断，不得只改提示词或后续生产参数。

## 评审循环

每个员工提交候选执行稿后立即进入总导演审判：

1. 读取员工 envelope。
2. 验证导演启动包、分镜层级结构和必需字段。
3. 检查来源追溯、导演命题、镜头目的、观众感受、连续性、空间证据、导演学院规则、分镜医生诊断、转场医生合同、观众盲测 QC 和分镜文件完整性。
4. 按员工评分量表给出 0 到 100 分。
5. 达到通过线后进入总导演签署判断。
6. 未达到通过线，或达到通过线但总导演仍不满意时，把评审记录退回同一员工重做。
7. 重做后的内容草案重新进入同一评审流程。
8. 人工审核不通过时，先运行 `user-feedback-triage-agent`，再把反馈映射到对应员工返工。

默认通过线：

- 普通内容：85 分。
- 关键内容：90 分。关键内容包括导演阐述、视觉连续性、分镜组与分镜 ID、空间调度、摄影与分镜、后续部门导演要求和导演 QC。

评分未达标时，不得由总导演代理绕过员工重写执行稿。总导演代理只能修复明显格式错误；创意、规划、判断和导演实质内容必须由对应员工按总导演命令返工。评分达标但总导演不签署时，同样返工。

## 最终综合回复

所有内容草案和分镜文件通过评审并被总导演签署后，总导演代理必须报告：

- 接收的项目办公室导演启动包摘要；
- 导演部当前正式包根目录；
- 正式包根目录、季/集/分镜组/分镜文件层级；
- 已生成或更新的分镜文件清单；
- 总导演签署状态；
- 各员工内容评分和返工次数；
- 已裁剪职责；
- 未关闭反馈、阻塞项和后续交接建议。
