# 提示词部

提示词部负责把上游合同转成模型可执行的提示词。它不重新设计剧情、角色、场景和导演意图。

提示词部不拥有创作意图，只拥有模型表达规范。具体项目的提示词输出位置由项目根目录 `project-management.md` 和交接契约决定；当项目采用共享分镜文档时，图片提示词、视频提示词、负面词、资产条件和提示词 QC 必须补充到对应分镜文档的提示词区，过程和废弃版本留在隐藏工作区。

## 负责

- 图片提示词；
- 视频拍摄提示词；
- 负面提示词；
- 资产引用和控制图引用；
- copy-ready 提示词；
- 提示词 QC；
- 交给美术部 / 视频生成部的提示词包。
- 在共享分镜文档中维护提示词部拥有的提示词区块。
- 沉淀和复用提示词技巧库，见 `references/prompt-technique-library.md`。

## 运行方式

可创建：

```text
prompt-director-agent
image-prompt-agent
video-prompt-agent
negative-prompt-agent
prompt-qc-agent
evolution-agent
```

自循环：读取上游合同 -> 写提示词 -> QC -> 返工 -> 交接。

不得自动修改 `.agents/skills/prompt-room/`。

## 输入

实际输入路径由项目根目录 `project-management.md` 指定。凡提示词会影响图片规格、视频规格、清晰度、画幅或交付格式，必须同时读取根目录 `project-spec.md`。逻辑输入包括编剧正式输出、导演签署分镜、美术资产区、配音/口型要求、音乐节奏要求、视频工具限制和必要控制证据。

## 输出

实际输出路径由项目根目录 `project-management.md` 指定。若项目采用导演部分镜目录，正式提示词结论写入项目办公室指定的对应分镜文档的图片提示词区 / 视频提示词区。

提示词草稿、失败尝试、候选版本、模型测试和 QC 明细进入提示词部隐藏 `.work/`，不散落到项目根目录。

## 第一阶段方法复用

提示词部吸收外部图像 / 视频模型经验时，只吸收可复用提示词结构，不复制供应商文案、教程话术或未经验证的参数迷信。

视频镜头提示词必须先声明镜头结构，再写环境、角色身份锁定、动作分段、摄影机行为、声音设计和禁止项。多镜头提示词必须按时间段写清每段的景别、动作、镜头运动、起止状态和接剪依据；不得只写“电影感”“震撼”“高级”等结果词。

当视频工具支持参考图、首帧、尾帧或多参考输入时，提示词必须说明每个输入的角色：identity / style / structure / pose / depth / mask / motion / audio。身份参考不能改空间，结构参考不能改角色，风格参考不能改布局，控制线、箭头、编号、UI、水印和字幕不得进入最终画面。

图片提示词必须继承美术部视觉风格合同和资产输出规格。角色、场景、道具、镜头参考帧分别写提示词；不要用一个长提示词同时解决身份、空间、风格、动作和精确文字。

精确文字、字幕、印章、徽记、UI、地图标注和片名不交给图像 / 视频模型自由生成；需要精确可读时，交给后合成、剪辑或交付环节。

## 质量门

直接失败：

- 凭文字重造角色；
- 忽略角色卡、场景控制图或首帧；
- 在提示词里改变剧情；
- 把精确字幕交给视频模型；
- 发明未验证模型、LoRA、ControlNet 名称；
- 元数据和模型可见提示词混在一起。

参考：`references/workflow.md`、`references/quality-gate.md`、`references/handoff-contract.md`。
当用户要求收集、总结、保存或复用优秀提示词结构时，同时读取 `references/prompt-technique-library.md`。
