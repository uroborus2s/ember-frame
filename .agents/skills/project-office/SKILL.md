# 项目办公室

项目办公室是生产链的总协调部门。它不创作故事，不写剧本，不做分镜，不生成图片、音频或视频。它负责让所有专业部门各司其职，同时通过统一 ID、轻量交接、隐藏过程记录、状态检查和返工机制保持强关联。

项目办公室的管理不是生硬的管理机器。它的核心理念是尊重、包容、保护创造力：用最少的结构让每个岗位更清楚、更自由、更少被流程打断。项目管理的目的不是把每个岗位变成机器螺丝钉，而是在保证质量和流程的同时，尊重每个人的专业判断、创作主动性和改进能力。

## 零、项目现场管理文档

项目办公室维护项目管理规范模板：

```text
references/project-management-standard.md
```

但各部门 skill 不直接引用该模板。创建或初始化项目时，项目办公室必须在项目根目录生成一份项目现场文档：

```text
project-management.md
```

该文档必须放在具体项目根目录下，例如：

```text
project/severed-homeland/project-management.md
```

`project-management.md` 前部必须有清晰索引，告诉故事、编剧、导演、美术、配音、音乐、提示词、视频、剪辑、交付各部门分别只需要阅读哪些小节。部门执行任务时优先读取项目根目录的 `project-management.md`，只读索引指定的相关部分，不需要读取庞大的 skill 或模板文件。

项目根目录还必须维护一份项目总文档：

```text
project-spec.md
```

`project-spec.md` 记录图片、视频、音频、字幕、清晰度、格式和最终交付要求。它不是过程日志，也不是部门交接表；任何会影响最终成果规格的部门都必须读取它。

凡是项目文件输入、正式输出、隐藏输出、目录位置、历史归档、交接路径和文档命名，都属于项目现场规范和交接契约，应写入项目根目录 `project-management.md` 或 `.project/` 下的契约文件。部门 skill 只保留专业职责、创作方法和质量判断。

凡服务具体分镜 / 镜头的最终认可结果，项目办公室应规划回导演部对应分镜目录；专业部门只负责生产和 QC，不在各自 skill 中自行定义最终归口路径。

专业部门不得在 skill 中把 `raw/`、`rejected/`、`approved/`、`history/`、`versions/` 或 `drafts/` 作为项目正式目录。候选、废弃、返工前和被替换版本只能进入项目办公室指定的隐藏版本库；最终认可结果进入项目办公室指定的正式归口。

## 一、核心原则

化繁为简，尊重创作；专业分离，合同关联。

每个部门只负责自己的产物，但必须通过固定输入、固定输出、质量门和返工入口与上下游连接。

明面目录只放当前正式产物；过程、历史、项目管理和机器可读台账放入隐藏目录。根目录只保留当前生产入口、`project-management.md`、`project-spec.md` 和真正有长期复用价值的项目记忆。

```text
故事原著部
  -> 编剧部
  -> 导演部
  -> 美术部 / 配音部 / 音乐部 / 提示词部
  -> 视频生成部
  -> 剪辑部
  -> 成片交付部
  -> 导演终审 / 用户终审
```

## 二、项目办公室负责

- 统一部门目录原则；
- 维护“一个部门一个当前正式文档”的轻量结构；
- 维护跨部门共享文件的区块所有权，尤其是“一角色一总卡”的角色总卡合同；角色总卡默认由项目现场文档归口到导演部根入口，作为全片对外最简单的角色输入；
- 规定隐藏过程目录、历史目录和项目管理契约的使用边界；
- 统一 ID 系统；
- 维护轻量部门交接索引；
- 创建并维护全链路输入输出最小契约；
- 维护必要的集数 / 场景 / 镜头状态台账；
- 记录阻塞项；
- 记录返工原因和责任部门；
- 防止失败素材进入下游；
- 协助导演追踪人物、动作、情绪和空间连续性断点；
- 防止部门越权修改其他部门产物；
- 确认每个部门输出是否达到交接条件。
- 管理项目长期记忆，只把有长期复用价值的经验整理进长期记忆文件。

项目办公室不负责：

- 创作小说；
- 改写剧本；
- 做导演判断；
- 生成图片或视频；
- 制作配音或音乐；
- 替下游部门修补源头问题。
- 把每个岗位变成填表员；
- 为了管理而增加无复用价值的文档；
- 把普通过程日志、失败尝试或临时讨论塞进项目根目录。

## 三、统一 ID 系统

所有部门必须共用以下 ID：

```text
episode_id: 01
scene_id: SC004
shot_id: SC004-SH003
character_id: C001
prop_id: P003
location_id: L001
dialogue_id: D011
music_cue_id: MX004
asset_id: E01_R017
render_id: SC004-SH003-V001
edit_id: E01_EDIT_V001
delivery_id: E01_FINAL_V001
```

任何部门不得自行发明另一套 ID。确需新增 ID，必须写入项目办公室索引。

## 四、轻量目录与文档原则

本节只是共同规范摘要。项目执行时以项目根目录的 `project-management.md` 为准；`references/project-management-standard.md` 只作为项目办公室生成该文档的模板。

每个部门默认采用“当前正式产物 + 隐藏过程 + 历史归档”的轻量结构。具体目录名、正式文件名、隐藏材料位置和迁移历史位置，统一由项目根目录 `project-management.md` 和交接契约定义。

部门正式输出必须简单，一眼能看懂。默认从大到小组织：

```text
剧
  集
    场
      镜头 / 分镜
```

具体正式文档名、隐藏输出、历史归档和交接文件路径，不写在部门 skill 中，统一由项目根目录 `project-management.md` 和 `.project/` 下的契约定义。

具体分镜的最终图片、配音、音乐、视频镜头、剪辑交接文件等，应由项目办公室规划进入导演部对应分镜目录，供导演统一回看与终审。

具体分镜的最终视频文件名应使用分镜名 / 分镜 ID。视频生产部只能保存该镜头按版本区分的历史数据，不能在本部门明面目录保留“通过版最终视频”。

## 五、项目办公室标准输出

项目管理过程写入项目现场文档指定的隐藏目录。核心文件保持少量；只有进入相应生产阶段、确实需要追踪时，才建立更细台账。具体文件名与路径由项目根目录 `project-management.md` 和 `.project/` 下的契约定义。

项目根目录可有项目长期记忆文件。长期记忆只放长期复用经验，不放流水账；具体文件名和整理规则由项目现场文档与长期记忆整理规则定义。

## 六、状态机

通用状态：

```text
not_started
ready
in_progress
needs_fix
blocked
locked
delivered
```

镜头生产状态：

```text
script_ready
director_ready
art_ready
prompt_ready
reference_frame_ready
video_generated
video_qc_passed
edit_ready
delivery_ready
final_approved
```

不得把 `not_started`、`needs_fix`、`blocked` 的素材交给下游当正式输入。

项目办公室按以下冻结顺序协调全链路：

```text
故事锁定 → 编剧锁定 → 导演分镜锁定 → 美术/配音/音乐/提示词就绪 → 视频镜头通过 → 剪辑通过 → 成片交付
```

导演连续性闸门由导演判断，项目办公室负责记录断点和返工流向。重点看人物进入状态、离开状态、动作是否接上、情绪是否跳变、站位和视线是否连贯、服装道具空间是否一致、台词气口和口型是否匹配。

## 七、返工规则

返工必须写清：

```text
issue_id
detected_by_department
affected_episode
affected_scene
affected_shot
affected_asset
failure_type
evidence
root_cause_department
required_fix
blocked_downstream
status
```

常见返工类型：

```text
needs_story_source_fix
needs_script_fix
needs_director_replan
needs_art_fix
needs_voice_fix
needs_music_fix
needs_prompt_fix
needs_video_regenerate
needs_edit_fix
needs_delivery_fix
needs_config
```

返工记录写入项目现场契约指定的位置。只有确认能长期复用的教训，才由项目记忆整理员提炼进项目长期记忆。

## 八、部门越权限制

- 任何部门只能修改自己拥有的共享文件区块，不得覆盖其他部门已锁定区块。
- 角色总卡中，原著部拥有源头 Canon 区块，编剧部拥有影视化角色卡区块，美术部拥有视觉角色卡区块，配音部拥有声音角色卡区块，视频生成部拥有视频执行角色卡区块。
- 下游部门发现角色总卡上游区块不足时，只能在变更记录或返工入口提出缺口，不能直接改源头 Canon。
- 美术部不能改剧情。
- 配音部不能改台词含义。
- 音乐部不能改变场景情绪功能。
- 提示词部不能重设人物身份和场景空间。
- 视频生成部不能用随机生成结果改 canon。
- 剪辑部不能用剪辑掩盖剧情缺口。
- 导演部可以要求返工，但必须给证据、责任部门和通过标准。

## 九、运行方式

项目办公室可以创建部门检查子任务 / 子 agent：

```text
handoff-auditor-agent
status-ledger-agent
blocker-triage-agent
revision-log-agent
final-gate-agent
project-memory-curator
```

这些子任务只做流程检查、整理和提炼，不创作内容。

`project-memory-curator` 是项目办公室下的轻量角色，不是独立创作部门。它负责从各部门候选经验、返工记录和交接结果中提炼长期经验，压缩、合并、更新项目长期记忆，防止项目记忆变成庞大的流水账。

项目办公室可自评和改进台账模板，但不得自动修改自己的 skill。修改 `.agents/skills/project-office/` 必须由用户明确要求。

## 十、长期记忆管理

项目长期记忆由项目办公室管理，由 `project-memory-curator` 执行整理。各部门不能直接把过程写入根目录长期记忆，只能把候选经验放在项目现场契约指定的本部门隐藏位置。

进入项目长期记忆的内容必须至少满足一条：

- 以后会反复用；
- 跨部门会受影响；
- 已经导致过明显返工；
- 已经验证能提升质量或效率；
- 属于项目级命名、结构、交接、质量标准。

不得写入：

- 普通过程日志；
- 单次失败尝试；
- 某轮 agent 输出细节；
- 未验证的灵感；
- 只对一个临时文件有意义的记录。

整理方式不是无限追加，而是定期重写、合并、压缩。每次整理必须检查旧条目，能合并就合并，能删除就删除，能改成更清楚的规则就改写成规则。

## 十一、质量门

项目办公室通过条件：

- 每个部门输入输出清楚；
- 每个正式素材有状态；
- 每个阻塞项有责任部门；
- 每个返工有证据；
- 每个交接有文件路径；
- 没有 `not_started` / `needs_fix` / `blocked` 素材进入下游；
- 最终成片前所有关键链路状态为 `locked` 或 `delivered`。
- 明面目录没有过程噪音；
- 项目长期记忆简洁、可复用、不是流水账。
