# 项目长期记忆整理规则

`project-memory.md` 是项目根目录下的长期复用记忆，不是过程日志，也不是返工流水账。

本文件从属于项目根目录的 `project-management.md`。`project-management-standard.md` 只是项目办公室用于生成项目现场文档的模板；各部门按项目根目录文档执行。

## 一、负责人

`project-memory.md` 由项目办公室管理，`project-memory-curator` 负责整理。

`project-memory-curator` 是 project-office 下的轻量角色，不是独立创作部门。它不创作故事、不改剧本、不做导演判断，只做经验筛选、压缩、合并和格式维护。

## 二、来源

候选经验来自：

```text
department/.work/memory-candidates.md
.project/revision-log.jsonl
.project/handoff-index.json
.project/blockers.md
```

各部门只能提交候选经验，不能直接把过程写进 `project-memory.md`。

## 三、准入标准

进入 `project-memory.md` 的内容必须至少满足一条：

- 以后会反复用；
- 跨部门会受影响；
- 已经导致过明显返工；
- 已经验证能提升质量或效率；
- 属于项目级命名、结构、交接、质量标准。

不得写入：

- 普通过程日志；
- 单次失败尝试；
- 某轮 agent 输出细节；
- 没有验证的灵感；
- 只对一个临时文件有意义的记录；
- 可以在 `.work/` 或 `.history/` 中追溯、不需要指导未来生产的材料。

## 四、整理方式

整理不是追加日志，而是重写记忆：

1. 先读完整 `project-memory.md`。
2. 再读候选经验和相关返工记录。
3. 删除过时、重复、只描述过程的条目。
4. 合并相似经验。
5. 把含糊描述改写成可执行规则。
6. 每条保留来源，但来源只写简短路径或事件，不展开过程。

## 五、推荐条目格式

```text
## 经验标题

适用范围：
结论：
原因：
以后怎么做：
来源：
```

条目必须短。不能把一整段复盘、聊天记录、工具输出或详细失败过程复制进来。

## 六、整理频率

默认按关口整理：

- 每完成一次部门交接，检查是否有候选经验；
- 每完成一集，做一次轻总结；
- 每次重大返工后，必须判断是否产生长期经验；
- 每季完成后，做一次完整复盘。

不要每日机械总结。项目记忆宁可少，也要准。

## 七、根目录原则

根目录只给人看当前和长期有用的内容。

```text
project-memory.md
```

只保存压缩后的长期规则。过程、历史、证据、流水记录全部留在隐藏目录。
